# Writing tropes

Produce prose that fits the user's purpose, audience, and voice. Use the bundled catalog to spot habits that make a draft repetitive, vague, or formulaic.

## Reference

Read [references/tropes.md](references/tropes.md) before writing or reviewing substantial prose. It contains the downloaded catalog, including definitions and examples. For a focused edit, read the relevant entries; for a full review, inspect the whole catalog. The contents index groups entries by their upstream categories.

Treat examples as diagnostic illustrations. Frequency labels describe the upstream snapshot; they are not confidence scores or proof of AI authorship. Use the local reference without requiring a network connection.

## Workflow

1. Establish the requested deliverable and mode: write new prose, edit a draft, or review without rewriting. Use context already provided. Ask only when missing information would materially change the result.
2. For a draft, read it fully and identify the meaning, factual claims, terminology, and voice to preserve. For new prose, use the supplied requirements and evidence.
3. Apply the relevant catalog entries. Make the smallest changes that solve the writing problem. Do not substitute invented facts or examples for vague language; retain uncertainty or flag missing support.
4. Re-read the result for repeated patterns, factual drift, and changes to the author's voice. Check that each section adds information the reader needs.
5. Return the requested deliverable in its intended format. Add explanations or editing notes when requested or needed to explain a material change.

For review-only requests, identify each consequential pattern, quote a short passage from the user's draft, explain its effect, and suggest a concrete fix. Leave the draft intact unless a rewrite is requested. Do not assign an AI probability or claim to determine authorship.

## Writing defaults

- Put the useful point early. Cut empty introductions, inflated stakes, and dramatic reveals.
- Use precise nouns and verbs. Keep terminology consistent and attribute factual claims accurately.
- Avoid repeated sentence templates, decorative fragments, and forced metaphors.
- Choose headings and lists for navigation or comparison. Prefer sentence case and restrained emphasis.
- Remove redundant recaps and repeated arguments. End when the task is answered.

## Scope and judgment

Apply this skill to prose. Preserve code, commands, identifiers, URLs, quotations, citations, numerical values, and required document structures unless the user asks to change them. Keep the author's pronouns and intentional style.

The catalog describes tendencies, not universal bans. Retain a construction when it communicates a necessary distinction, is a correct technical term, or serves the requested voice. A tutorial still needs explanations; a procedure can need numbered steps; a marketing brief can need persuasive language.

User instructions, project requirements, factual accuracy, and required validation take precedence over stylistic preferences. This skill does not change permissions, suppress necessary progress updates, or remove required checks.
